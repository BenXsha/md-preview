# 主题许可自查 / Theme license audit

CSS 也是有版权的作品。"能下载到" 不等于 "可以再分发"。这份清单用来在 30 秒内判断一个主题能不能
放进你的仓库 / 发行版，或者只能在本机自己用。

## 30 秒清单

1. **仓库根目录有没有 `LICENSE` / `COPYING` / `LICENSE.md`？**
   - 有，且是 MIT / Apache-2.0 / BSD / CC0 之类的宽松许可 → 可以再分发，注意保留版权声明与许可全文。
   - 有，但是 GPL 系 / CC-BY-NC / CC-BY-ND / 自定义条款 → 先看清要求（GPL 系对分发方式有约束；
     NC/ND 不适合放进宽松许可项目）。
   - **没有** → 默认「保留所有权利」，**不要重新分发**。
2. **文件头有没有许可或归属声明？** 有些作者的许可见于 CSS 注释而不是仓库根目录，例如
   `/* … Copyright … MIT License http://opensource.org/licenses/MIT */`。这类声明同样有效，
   而且分发时必须原样保留。
3. **仓库/包元数据的许可字段怎么说？** GitHub 仓库页右侧 License、`package.json` 的 `license`、
   `MANIFEST`、`.reuse/dep5`（REUSE 规范）都是证据；以最明确的一份为准，冲突时按更严格的处理。
4. **子资源是不是独立的第三方作品？** 主题常带字体、图标、图片，它们各有各的许可：
   - 字体：SIL OFL 1.1（须随附 `OFL.txt`）、Apache-2.0、GUST Font License、或公有领域；
   - 图标：常见 CC-BY 3.0/4.0（**需要署名**）或 MIT；
   - 内嵌 `data:` SVG、雪碧图：同样属于作品。
5. **是不是衍生作品？** 如果 CSS 明显改编自另一个项目（文件里常留着原项目名/网址），
   衍生物的许可取决于原作者是否授权；只保留一句归属声明通常不够，除非原作者给的是宽松许可并且
   你保留了完整许可文本。
6. **不确定就用最保守的方案：只本地使用，不打包、不再分发。**

## 三种情形该怎么处理

| 情形 | 做法 |
| --- | --- |
| 许可明确（MIT / Apache-2.0 / BSD / OFL …） | 可以收录进目录、可以打包；保留版权与许可文本，写明出处 |
| 许可不明 / 保留所有权利 | **只在本机自己用**：自己下载、自己放主题目录。不要在仓库里分发、不要做成安装包、不要代为托管镜像 |
| 用户自带主题 | 由使用者对许可负责。工具只提供 `--install-theme` 这个搬运通道 |

## 本项目的做法

- 仓库自带两个主题（`default` / `default-dark`），是**本项目原创的 MIT 资源**，可自由修改分发。
- `--fetch-themes` 的目录里只收录**许可明确**的来源，并在输出与文档里写明许可与出处；
  下载由用户显式触发，直接来自上游仓库（本仓库不镜像、不打包这些 CSS）。
- 任何其它主题都走 `--install-theme`，许可由使用者自行确认。
- 主题文件在本项目里始终以 `<link>` 原样引用，不做改写，因此作者的版权声明不会被抹掉。

## 自己发布主题时

建议（同时也是让别人敢用你的主题的最短路径）：

```css
/* my-theme.css
 * SPDX-License-Identifier: MIT
 * Copyright (c) 2025 Your Name
 */
```

- 加 `LICENSE` 文件，并把字体/图片等子资源的许可与出处单独列一段（或放 `THIRD-PARTY` 文件）。
- 用 `--install-theme` 的用户会把 `.css` 放到自己的主题目录；若你的主题依赖子目录（如 `fonts/`），
  在 README 里说明目录结构。
- 遵循 DOM 契约（见 [`../themes/README.md`](../themes/README.md)）即可在任何遵循同一约定的渲染器里工作，
  不必依赖某个特定应用。
